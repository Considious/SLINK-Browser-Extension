# Event performance and PDA source-connection hotfix

Stable extension 0.19.13; PDA 0.4.113. Scoped emergency release, not promotion of the audit branch.

PDA starts a valid cached runtime before downloading sources. A throttled background manifest check discovers an update; a changed revision downloads on the next normal page load. Cold/update downloads use two workers rather than launching every source request at once. Refused/time-limited raw GitHub source downloads try the same public repository path on jsDelivr. The actual fallback manifest returned HTTP200 in verification. No API keys, target data or settings are sent to the CDN. Known-working cache is replaced only after successful readiness, and source failures retain it. Retry explicitly tries a fresh download. A first installation with neither reachable source host nor cache cannot run SLINK; it shows a compact retry control without blocking Torn.

Extension/PDA Xanax decoration now ignores unrelated attack/log text changes, coalesces relevant changes, skips energy searches where no Xanax control exists, and pauses when inactive. Real clicks still read current energy and require confirmation when appropriate. PDA uses visibility rather than unreliable WebView focus. Extension profile scraping observes only visible, focused profile pages, and its custom chat-button observer reacts to context/header insertion rather than every page mutation. Extension window blur releases module workers; visible but unfocused windows cannot claim them.

Validation: production loader VM refusal/mirror/cache/update/offline tests; 10,000-mutation production-helper tests on both platforms; retained extension startup/permissions tests plus focus/blur; complete PDA direct-source syntax/build check, launcher17756bytes under unchanged18000budget. Real headless Edge MutationObservers on synthetic attack pages produced zero whole-document rescans for unrelated frames on both platforms, while live 900/950-energy confirmation and hidden/resume worked. A fixture first omitted the PDA runtime's global parameter; corrected fixture wrapper, not product assertions. Physical PDA devices and full authenticated event gameplay remain unverified; no claim all possible lag is eliminated.

No user-data reset, API-key deletion, permission/theme/asset change, automatic cloud restoration, new API polling or gameplay automation. Existing users must update the PDA launcher to receive loader recovery; already-installed Chrome extensions receive packaged JavaScript only after their extension update.
